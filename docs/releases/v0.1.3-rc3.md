# Cache Vault v0.1.3-rc3 (release candidate)

**Status:** Release candidate — not a final release. **No git tag.** Do not replace the shipped **v0.1.2** desktop release.

**Source commit:** packaging from `feature/cache-vault-desktop-hardening` after Phase 6.1 acceptance.

## Scope split (truthful)

### Desktop (Windows exe in this zip)

Everything in **v0.1.3-rc2** desktop scope, plus Phase 6 and Phase 6.1:

| Phase | Topic | Status |
|-------|--------|--------|
| 1–5.5 | Same as rc2 (scroll, paste-from-selection, editable copies, HTML bundles, UI IA, proof export, capture rules, Safes) | Done |
| 6 | Vault Macros setup + smart filters | Done |
| 6.1 | Live macro execution (hotkeys, text shortcuts, picker, paste/type, receipts) | Done |

Highlights since rc2:

- **Vault Macros** screen — create/edit macros, trigger types, output modes, run counts
- **Text shortcut expansion** — e.g. `;sig` expands in foreground apps (Notepad verified)
- **Global macro hotkeys** — non-conflicting per-macro bindings
- **Macro picker** — `Ctrl+Shift+M` at cursor; number key or Enter to execute; Esc closes without clipboard mutation
- **Clipboard paste / keystroke type** delivery to foreground window
- **Macro execution receipts** — no full sensitive macro body stored
- **Clipboard restore** after macro paste (optional setting)
- **CTk crash-dialog fix** — Run button no longer triggers "Something went wrong" after macro refresh

### Mobile companion (Android — separate artifact)

Requires **Mobile Access ON**:

- Read-only LAN bridge on port **8742**
- `/mobile/v1/status`, `/mobile/v1/clips`, `/mobile/v1/recently-removed`
- Safe metadata in clip payloads when present
