# Cache Vault v0.1.3-rc5 (release candidate)

**Status:** Release candidate — not a final release. **No git tag.** Do not replace the shipped **v0.1.2** desktop release.

**Source commit:** `66cf359` — RC4 scope plus **no-restart pairing hot-reload** for the desktop mobile bridge.

## RC5 = RC4 + pairing hot-reload

```text
RC4 + no-restart pairing hot-reload
```

Everything in **v0.1.3-rc4**, plus:

| Area | Change |
|------|--------|
| Desktop bridge | Paired devices reload from disk before auth — **no CacheVault.exe restart after pairing** |
| Regression | `test_pair_hot_reload_without_restart` + `scripts/pairing_hot_reload_smoke.py` |

### Desktop (Windows exe in this zip)

Everything in **v0.1.3-rc4**, including:

- Luxury vault UI + Mobile Inbox receiver
- First-use guide, receipt tooltips, empty-state help
- `POST /mobile/v1/inbox/send` with receipt stamping
- Vault Macros live execution (from rc3)

### Mobile companion (Android debug APK — separate artifact)

Same RC4 Android scope:

- Manual Setup pairing
- Share Sheet Simple Mode
- Send to PC → desktop Mobile Inbox

Requires **Mobile Access ON** on the PC. Pair from Settings, enter credentials on phone — **no desktop restart required**.

## What changed since v0.1.3-rc4

| Area | Change |
|------|--------|

| Usability | Removes hidden “restart exe after pairing” trap |

## Honest limitations (not claimed in this RC)

- **No cloud sync** — paired local Wi-Fi bridge only
- **Safes are not encrypted** — organizational metadata only
- **Image/file send from Share Sheet** — deferred
- **Sensitive warn-before-send** — deferred/planned
- Android APK is debug/internal candidate only
